# 需求单模板

> **用途**：提需求或报 Bug 时先填这份单子。核心是第 3 节「范围边界」——
> 把「允许改什么、禁止改什么」写死在纸上，AI 就没法越界。
>
> **使用方法**：复制为 `docs/DEV/tickets/<日期>-<简短标题>.md`，完成后把状态改为「已完成」。

---

| 项 | 值 |
|----|-----|
| **类型** | 新功能 / Bug 修复 / 优化 / 重构 |
| **优先级** | P0（阻塞） / P1（重要） / P2（常规） / P3（锦上添花） |
| **提出日期** | YYYY-MM-DD |
| **状态** | 待评估 / 已批准 / 进行中 / 已完成 / 已驳回 |
| **关联功能档案** | `../features/xxx.md` |

### 3.2 禁止改动

> **明确写死不要碰的东西。** 这是防止「修一个问题冒出三个新 bug」的关键。
