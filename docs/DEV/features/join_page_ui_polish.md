## 1. 目标：解决什么问题

开发者认为添加页「面板多、输入框多、整体偏乱」，希望在**保留现有信息架构与左右分栏**
的前提下，把整个页面的组件尺寸 / 边框粗细 / 圆角 / 间距统一到一版新的设计稿上，
使视觉更克制、更整齐。

输入素材（均在 `素材/新建文件夹 (2)/`）：

- `GameLibraryWindow.json` —— Figma Raw 插件导出的结构化设计数据（画布 1280×720）
- `GameLibraryWindow.png` —— 设计稿全窗口截图（1280×720）
- `Section - 待入库游戏列表.png` —— 列表区段 1:1 导出（666×329）

## 2. 用户可见行为

- 布局、分栏比例、三模式（单个 / 批量 / 智能）切换方式**完全不变**。
- 变的是：封面变大、输入框变矮且边框变细、标题字号变小、卡片更高更密、
  路径框更矮、模式切换栏与底栏文字略大、「新增文件夹」栏多了一圈浅边框和硬阴影。
- 所有交互行为（拖拽、抓取、锁定、切标题、批量入库、二次确认）逐位不变。

## 3. 设计思路：为什么这么做

### 3.1 尺度判定：设计值 = 逻辑像素（1x）

先用 PIL 对参考图做像素测量，与 JSON 数值逐项对照，确认**截图像素 = 逻辑像素**，
因此设计稿数值可直接照搬，无需换算：

| 元素 | JSON | 截图实测 | 结论 |
|---|---|---|---|
| 窗口画布 | 1280×720 | 1280×720 | 1x |
| 封面 Container | 157×229.5 | bbox 157×227 | ✅（含 −0.035rad 旋转） |
| 游戏名称框 | 314×62.2 | y 58→119（61 高） | ✅ |
| 待入库列表区段 | 666×329 | x 591→1256 / y 308→636 | ✅ |
| 游戏卡片 Article | 611×100 | y 89→189（100 高） | ✅ |
| 底栏 取消 / 批量入库 | 70×39 / 127×50 | 780→849 / 860→986 | ✅ |

### 3.3 一个关键发现：设计稿里有一处「现状就是对的」

底栏按钮组实测中心 x = 883，右栏中心 x = 923.5 —— **设计稿本身就把按钮组左移了 40.5px**。
这与 `action_buttons.dart:36` 的 `Transform.translate(offset: Offset(-40, 0))` 逐像素吻合。
⇒ **这不是历史 hack，是设计意图，禁止"顺手修正"对齐。**

同理实测确认「已经一致、无需改动」的还有：左栏 475 / 右栏 665 / 间距 20（flex 5:7）、
截图轮播 475×267（`screenshot_carousel.dart` 已用 `16/9`）、模式切换栏居中
（`SwipeSwitcher` 内 `Column` 默认 `center`）、两个区段圆角 = 0。

- **路径框水平位置**：第一轮**未**照搬，**第二轮已按开发者要求改为「与信息区同排」**
  （`信息 : 目录框 = 2 : 1`），既落在设计稿「信息区右带」的位置上，又消除了卡片底部留白。
  详见 §11.4。
- **会社联想胶囊位置未照搬** → 设计稿把它叠在开发商框右下角。本仓右栏窄，
  叠层与 `Wrap` + `IntrinsicWidth` 的既有坑（见 `MEMORY.md §4`）叠加极易溢出，
  **保留现状（框下方左对齐）**，仅改字号/圆角/边框。
- **`_buildCollapsedSummary` 本来就是居中的** → 父级 `Column` 默认
  `CrossAxisAlignment.center` + 胶囊自身 shrink-wrap，所以"居中"这一项无需改代码，
  只调了圆角与内边距。（教训：动手前先确认真实渲染，别照着设计稿重复劳动。）

### 11.3 🔴 模式切换栏「连体选项卡」——第一轮**只改了边框粗细，漏了结构**

第一轮把这一项误判为「居中已相符 ✅」，只调了边框 1.5→1 / 内边距 / 字号。
第二轮重新对设计稿做像素测量后确认：**设计稿的模式切换栏本身就是一枚贴在置入板块
顶边上的选项卡**，第一轮完全没做这层结构。

实测（`GameLibraryWindow.png`，1x）：

| 量 | 实测值 |
|---|---|
| 选项卡 bbox | x **830→1013**（宽 184）× y **280→307**（高 28） |
| 顶部圆角 | **≈14**（= 高/2，即**上半圆**） |
| 与板块的间隙 | 板块顶边线在 **y=308**，选项卡底边在 y=307 → **贴合（0~1px）** |
| 选项卡水平位置 | 中心 921.5 ≈ 置入板块中心 923.5 → **居中** |

实现（`swipe_switcher.dart`）：

1. 去掉栏自身**底边框** → 底边线改由「置入板块顶边框」充当，**两条线合一**；
2. 顶部圆角 `Radius.circular(20)`（栏高 28，Skia 会把半径钳位到 14 → 与设计稿半圆一致）；
3. 与内容区之间的 `SizedBox(height: 4)` **删除**，选项卡直接坐在板块顶边上。

> ⚠️ 智能模式例外：其内容区是 `SingleChildScrollView` + 自带边框的卡片、**没有外框**，
> 若同样去掉底边框会出现「开口」（下半截没有边线）的怪样子，故
> `_currentMode == ImportMode.smart` 时保留底边框。

> ⚠️ 关键技术前提：Flutter 的 `Border` **只在「可见色一致」时**才允许与
> `borderRadius` 共用（`box_border.dart:1030` 的断言）。本用例三条边同为
> `AppColors.border`、底边 `BorderSide.none`（不计入可见色）→ 走
> `BoxBorder.paintNonUniformBorder` 分支，安全。

### 11.4 卡片「目录框上移」——消除卡片底部留白

原结构是**两行**：`Row(封面 | 信息 | 操作按钮)` + `Padding(left:56, top:3)` 里单独一行路径框。
路径框只占左半，右半全空，卡片被 `minHeight: 100` 撑到 ~102。

改为**同行**：`封面 | (信息 : 目录框 = 2 : 1) | 操作按钮`，`minHeight: 100 → 70`。

| 项 | 改前 | 改后 |
|---|---|---|
| 卡片高度 | ~102 | **70 ~ 78**（无 `⇄` 68/有 78） |
| 目录框位置 | 独立第二行、左对齐 56 | 信息区右侧、同排居中 |
| 400px 高列表可见卡片数 | ≈3.9 | ≈5.5（**+40%**） |

配套两处细节：

- 目录框内 `Flexible` → **`Expanded`**：把 ✎ 顶到框右缘，还原设计稿
  「📁 — 路径 — ✎」三段式（原来 ✎ 紧跟在文字后面）。
- 目录框 Container 补 **`width: double.infinity`**（必需）：
  `InteractiveWrapper` 内层是 `AnimatedContainer(alignment: center)`，只给子级**松约束**，
  不显式撑满的话短路径会把框缩成一小块并居中偏移。这正是旧注释
  「让路径框占满可用宽度」想做但实际没做到的事。
- 等宽安全性：`信息 : 目录框` 都是 `Expanded`（tight），两者按比例缩放，
  **任何宽度都不会溢出**；卡片宽度需 ≥ 167px 才有富余，实际最小窗口远大于此。

## 12. 需求 1 · 添加页 UI 三处优化（2026-10-10）

用户真机截图反馈三项，一次性收口。

### 12.1 封面预览整体缩小 + 随框倾斜

| 项 | 改前 | 改后 |
|---|---|---|
| 封面框尺寸 | 150×208 | **138×190** |
| 图片旋转补偿 | `Transform.rotate(+0.035)` 反向抵消外框 | **删除**，图片随外框一起倾斜 |

- 根因（几何）：外框 `Transform.rotate(-0.035)` 后包围盒最低点
  `= center.y + (h/2·scale)·cosθ + (w/2·scale)·sinθ + shadowDy`；
  150×208 时 ≈215px，越过截图起始线 **213px**（字段列 208 + 间隙 5）→ 视觉上「压到截图」。
  缩到 138×190 后最低 ≈198px（含 hover 1.02 与阴影 5px），安全余量约 15px。
- 视觉口径：封面图**不再反向旋转** ⇒ 整体如「带角度放置的相框」，图片永远贴合框内。
- 探针实测（S2）：静止最低点 350.86 / 悬停 352.80，均 < 截图区 top 366.5 ✅。

### 12.2 相册功能迁到封面展示区

- **移除**「元数据匹配」板块内的相册入口（`metadata_section.dart` 的 `_buildGalleryEntry` 删除，-78 行）。
- **新增**封面展示区右下角相册按钮（`field_lock_button.dart` 的 `CoverSectionWithLock`），
  样式与锁定/删除按钮同级：黑底圆角 + `Icons.photo_library_outlined` + Tooltip。
- 复用 `CoverPreviewOverlay`（`lib/widgets/cover_preview_overlay.dart`）并**扩展三动作**：
  - `onUpload` → `join_controller.pickCoverFromGallery()`（选本地图**直接设为封面**）
  - `onSetCover` → `join_controller.applyCoverCandidate(path/url)`（本地路径或网络 URL）
  - `onDelete` → `join_controller.removeCover()`（**清除当前封面**）
  - `itemsProvider` 回调支持操作后刷新候选列表；不传三回调 = 旧只读行为（供需求 3 复用）。
- 语义（用户拍板）：**上传 = 设为封面；删除 = 清除当前封面**。
- 候选来源 `_coverCandidates()`：当前本地封面 + 抓取竖版封面（`cover_url`）+ 抓取横幅封面（`banner_url`）。
