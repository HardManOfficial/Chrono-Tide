## 0. 一句话产品定义

> **让玩家在玩完一款作品很久之后，还能回到当时，把那次经历完整地想起来。**

这不是统计功能的加强版，是**个人游戏回忆的容器**。
计时、图表、状态都是为了让回忆有骨架；真正的主角是玩家自己的截图与文字。

## 1. 决策摘要（已拍板，后续不得跑偏）

| # | 已定决策 | 落地含义 | 明确不做 |
|---|---|---|---|
| D1 | 采用方向 A「游玩手记」 | 内容挂在**每次游玩会话**上，不另起一套自由日记作为主线 | 不做脱离会话的纯日记本 |
| D2 | 过程截图是**用户个人资产 / 收藏** | 专门的存放位置、专门的索引、专门的浏览界面 | **绝不**混入 `screenshot_files`（元数据宣传截图）；不做"系统截图/超分截图"的接管 |
| D3 | 做**软件专属快捷键截图** | 玩家在游戏中按自家热键 → 自动存到"对应游戏"的收藏处 | 不依赖玩家手动选文件作为主路径（手动导入只作补充） |
| D4 | 做一个**专属界面**承载全部功能 | 不是新主界面、不加侧栏项；点击入口后进入 | 不把功能拆散到多个页面 / 设置项里 |
| D5 | 界面统计**单游戏记录簿** + **全局概览** | 一个界面、两个视图，可切换 | 不做第三个独立统计页 |
| D6 | 两个入口：**主页（主要）** + **每个游戏详情窗口** | 主页进默认全局视图；详情窗口进默认该游戏视图 | 不在库页、托盘、BPM 再加第三、第四个入口 |
| D7 | 主页是「代表功能」载体 | 主页已有全局游玩数据与折线图，且目前没有代表功能 | 不改主页为"记录簿专用页"，主页仍是主页 |
| D8 | **偏沉浸式**，有仪式感、成就感，**简单且美观** | 深色沉浸界面、里程碑、收集感、轻反馈 | 不做复杂表单、多层设置、配置项轰炸 |
| D9 | 像一款简单的小游戏，**快速入手、零使用负担** | 默认全自动；玩家只需要学一个热键；文字一律可选 | **不做**签到 / 积分 / 任务 / 排行榜 / 每日目标 / 弹窗催促 |
| D10 | 开发重点：主页折线图设计、状态视觉化、统计体验升级 | 见 §6.3 / §6.4 | 不重做计时内核（除非 §9 的风险项被批准） |
| D11 | 终极目标：**退坑之后仍能回顾，且记录尽可能完整** | 见 §7.6「回忆完整性清单」 | 不允许"为了简洁而丢历史" |

**建议但尚未拍板**（我的提案，等用户裁决，见 §12）：截图资产的落盘位置、状态事件是否落独立索引、

## 2. 三个设计原则（所有取舍的裁判）

1. **零负担优先**：凡是需要玩家"记得去做"的事，一律降级为可选；系统能自动拿到的，绝不问玩家。
   衡量标准：**玩家全程不主动操作，也能得到一份可用的记录**。
2. **不打断游戏**：游戏运行期间不弹窗、不抢焦点、不出提示条；所有反馈在游戏窗口内以极轻的形式出现，
   需要玩家决定的事一律等游戏退出后再说。
3. **回忆优先于数字**：当"统计更好看"和"回忆更完整"冲突时，选后者。
   例如宁可保留一条只有 20 秒的会话，也不要为了图表干净把它过滤掉。

### 非目标（写清楚，防止后续被加回来）

- 不是社交功能：不分享、不排行榜、不公开主页、不云端动态。
- 不是成就系统：徽章只是"回看时的注脚"，不设目标、不催完成、不显示进度条压力。
- 不是数据修复工具：统计口径的历史欠账（见调研报告 §5）另行处理，不塞进本功能的首期。
- 不是屏幕录制 / 录像 / 直播工具。

## 3. 谁会用、什么时候用

| 玩家类型 | 期待 | 本功能对他的承诺 |
|---|---|---|
| **记录型**（核心用户） | 想留下推游戏那几个月的感受与画面 | 完整的时间线、可补写、可导出、不会被误删 |
| **轻用户** | 偶尔想看看自己玩了多久、有没有通关 | 全自动，什么都不用做，打开就有内容 |
| **不感兴趣** | 只想管理游戏，不想被记录打扰 | 功能可整体关闭；关闭后不注册热键、不写文件、界面入口收起 |

四个使用时刻：**玩之前**（几乎无感）→ **玩之中**（按热键截图）→ **玩之后**（可选写两句）→
**很久以后**（回来翻）。价值密度集中在最后一步，但那一步的质量完全由前三步的"自动 + 不打扰"决定。

## 4. 用户使用旅程（核心章节）

> 下表「玩家操作次数」是本方案最重要的体验指标。目标：**单次游玩 ≤1 次主动操作，且可以全程为 0**。

| 阶段 | 玩家在做什么 | 系统自动做什么 | 玩家看到什么 | 主动操作 |
|---|---|---|---|---|
| **S0 首次进入** | 打开主页，注意到右下角折线图变了 | 读取已有 `sessions` / `daily_play_log`，把历史游玩"补成"初始记录簿；不写任何用户内容 | 折线图旁边多一个入口，标题是「我的游玩记录」之类，不解释、不引导教程 | 0 |
| **S1 玩之前** | 正常从主页或库页启动游戏 | 已有链路照常计时；新功能只在后台准备一个"本次会话容器" | 无变化。**不弹窗、不提示、不要求选状态** | 0 |
| **S2 玩之中** | 遇到想留的画面，按一下专属热键 | 判定当前游戏 → 捕获画面 → 存入该游戏的收藏处 → 写索引（时间 / 会话 / 游戏） | 极轻的"已收藏"反馈（见 §7.1）；游戏不失去焦点、不暂停 | 0～N |
| **S3 玩之后** | 关掉游戏，回到桌面 | 会话结算；把本次时长、截图、状态生成一张「本次游玩小结」；**不弹模态框**，只在主页 / 托盘以非阻塞形式出现一次 | 小结卡片：玩了多久、收了几张图、这是第几次；一个「写两句」入口和一个「跳过」 | 0（可跳过） |
| **S4 告一段落** | 决定通关或弃坑 | 状态变更记成**事件**（何时、从什么状态、到什么状态）；若玩家愿意，可附一段感想 | 一次专门的「落章」仪式（不是下拉菜单），可跳过 | 0～1 |
| **S5 很久以后** | 从主页点开记录簿，或从某个游戏的详情窗口点开 | 按时间线把会话、截图、文字、里程碑拼好；默认展示"最近一段"或"该游戏" | 沉浸式深色界面；可翻年份、可点某次会话看图与文字、可看到"当时玩了多久" | 1（点入口） |

### 旅程的三条硬规则

- **R1 任何时候都能跳过**：S3、S4 的所有输入都可选，跳过不产生空记录、不留红点、不二次提醒。
- **R2 任何时候都能补**：当时没截图、没写字、状态忘了标，之后都能补；补记不改变原始会话时间，
  只标注「后补」，避免伪造记忆。
- **R3 任何时候都能反悔**：删一张图、删一句话、改一次状态归属，都允许；不做不可逆确认轰炸，
  但删除走项目既有的回收站护栏（ADR-020 / 应用内 `isInsideAppStorage`）。

## 5. 体验问题清单与优化对策（核心章节）

> 这是"开发前就要整理好"的部分。每条都给出**玩家会怎么不爽**与**验收判据**，不只是列风险。

### A 组 · 上手与打扰

| # | 场景 | 玩家会怎么不爽 | 优化对策 | 验收判据 |
|---|---|---|---|---|
| A1 | 第一次听说这个功能 | 「又要学一套东西」 | 零配置、零教程、零引导蒙层；入口文案自解释；首次进入直接有内容（用历史数据撑起） | 新玩家不读任何说明，30 秒内找到并理解入口 |
| A2 | 不感兴趣 | 觉得软件变臃肿、热键占了我的键 | 设置里一个总开关「游玩记录」；关闭后**不注册热键、不写文件、入口收起**；默认开启但完全静默 | 关闭后进程内无热键注册、无新增磁盘写入 |
| A3 | 热键和游戏 / 超分 / 输入法冲突 | 一按就误触，或者根本没反应 | 默认选一个低冲突组合；设置里可改；**注册失败必须明确提示并给出换键入口**，不静默降级 | 热键被占用时，玩家能在设置里看到原因并改成功 |
| A4 | 游戏运行中弹出任何 Flutter 窗口 | 全屏游戏被切出来，体验直接崩 | 游戏期间**禁止任何模态框**；截图反馈用不改焦点的轻提示；需要决策的事全部延到会话结束后 | 全屏独占下按热键，游戏不失去焦点、不最小化 |
| A5 | 每次玩完都弹「写点什么」 | 三天后就烦了 | 小结卡片默认折叠为一行；同一游戏连续 N 次跳过后再不主动出现，只保留入口 | 连续跳过 3 次后不再出现任何主动提示 |

### B 组 · 专属截图（最容易翻车的一组）

| # | 场景 | 玩家会怎么不爽 | 优化对策 | 验收判据 |
|---|---|---|---|---|
| B1 | 按了热键，「到底存上没有？」 | 不确定 → 反复按 → 一堆重复图 | 一次极轻且明确的成功反馈（快门/缩略角标/一声轻响，可关）；失败也要反馈，且说明原因 | 盲测：玩家能立刻判断成功 / 失败 |
| B2 | 同时开了两款游戏 / 前台窗口是浏览器 | 截图被归到错的游戏 | 归属优先级：前台会话 > 唯一活跃会话 > 最近确认会话；**判定不确定时进「待归属」收件箱，绝不猜、绝不丢** | 多会话场景截图不丢失，且可一键改归属 |
| B3 | 游戏没通过软件启动 / 软件刚打开 | 「我明明在玩，它说不知道是哪款」 | 同上进「待归属」；事后在记录簿里一键归到某游戏某天 | 无活跃会话时按热键，图片仍存在且可找回 |
| B4 | 游戏以管理员运行 / 全屏独占 / 多显示器 | 热键收不到、或截出来是黑屏 / 错屏 | 见 §9：这是**技术前提**，需在开发前验证；产品侧先做好降级：明确提示"本次未捕获"并给「手动导入这张图」的补救 | 每种失败都有可读原因 + 一条补救路径，绝不静默 |
| B5 | 截图里有敏感 / 私密画面 | 不敢存、或存了被别人看到 | 复用项目 NSFW 管线（显式入队 + `NsfwImage` 渲染）；提供「私密」标记（默认打码、需主动揭示）；**不做云端上传** | 新目录下的图也能被检测与打码；私密图默认不裸露 |
| B6 | 以前用 PrintScreen / 超分截的图想收进来 | 「以前的不算数吗」 | 记录簿提供「导入已有截图」：选文件 → 归到游戏 / 日期（读文件时间做默认值） | 老图能进时间线，并标注「导入」 |
| B7 | 截图越攒越多，找不到 | 收藏变成垃圾堆 | 自动按「游戏 / 年月 / 会话」三级归档；记录簿内以缩略图流 + 时间轴浏览，不用文件路径 | 100 张图时仍能 2 次点击内定位某次游玩的图 |
| B8 | 删游戏 / 归档 / 重装后截图没了 | **个人资产被软件弄丢，最不可原谅** | 见 §8：建议资产独立于 `metaDataDir`；删游戏时**明确询问保留 / 一并删除**，默认保留；提供「回忆册导出」 | 删游戏后回忆仍可访问；导出物脱离软件也能看 |

### C 组 · 记录与文字

| # | 场景 | 玩家会怎么不爽 | 优化对策 | 验收判据 |
|---|---|---|---|---|
| C1 | 玩完正上头 / 正累，不想写字 | 被要求"记录"反而破坏心情 | 文字永远可选；输入框只有一行、无格式要求、无必填、无字数下限 | 空文字可直接关掉，不产生空卡片 |
| C2 | 想写长的（通关感想） | 一行输入框不够 | 会话手记是一行；**通关 / 弃坑里程碑**才提供可展开的多行区域，两者分开 | 长文有地方放，且不污染每次会话 |
| C3 | 忘记当时是哪一天 | 对不上时间 | 每条文字自动带会话起止时间；后补标注「后补于…」 | 任何文字都能追溯到一次具体游玩 |
| C4 | 状态是「已通关」但还在玩 | 系统自相矛盾、看着别扭 | 状态改为事件流；通关 / 弃坑后再次启动 → 轻问一句「又捡起来了？」，玩家可一键回到「游玩中」，也可保持 | 状态与时间轴不再矛盾，且不需要玩家懂状态机 |
| C5 | 误点把状态设成弃坑 | 一个重要节点被弄错 | 里程碑动作带确认；状态事件可编辑 / 删除，保留历史而不是覆盖 | 误操作可撤销，且不留下假历史 |

### D 组 · 回顾（价值兑现的地方）

| # | 场景 | 玩家会怎么不爽 | 优化对策 | 验收判据 |
|---|---|---|---|---|
| D1 | 打开是空的 / 一堆 0 | 「白做了」 | 即使玩家什么都没写，也用自动数据撑起一屏：时间线、时长、截图数、首次与最后一次 | 全新用户首次打开即有非空内容 |
| D2 | 记录太碎，一次会话一条，翻不到底 | 看不动 | 默认按「月 / 作品」聚合，点开才到逐次；提供"只看有截图的 / 只写感想的"轻量筛选 | 3 年内 300 条会话仍能一屏看清结构 |
| D3 | 想找"那一幕" | 记不清哪天 | 缩略图流 + 按游戏 / 年份浏览；不做复杂搜索作为首期必需 | 靠视觉能在 1 分钟内找到目标图 |
| D4 | 数字口径不一致 | 「上周显示 12 次，全部显示 9 次」 | 见调研报告 §5：长 / 短跨度口径、<60s 过滤、90 天清理三处分叉必须先统一，再谈可视化 | 同一区间在任何视图数字一致 |
| D5 | 玩完很久回来，界面像后台报表 | 没有"回到当时"的感觉 | 沉浸式深色空间、以图为主、文字其次；状态用视觉语言（见 §6.4），不用表格 | 主观走查：像翻相册，不像看报表 |

### E 组 · 性能与稳定

| # | 场景 | 玩家会怎么不爽 | 优化对策 | 验收判据 |
|---|---|---|---|---|
| E1 | 全局概览要扫全库几百个目录 | 打开卡一下 | 增量索引 + 缓存；沿用 `StatsAggregator` 纯函数，但把全库遍历结果缓存并在会话结束时失效 | 千款游戏打开 <1 秒（真机验收项） |
| E2 | 阅历日历不刷新（已知缺陷） | 今天玩的，日历还是灰的 | 在会话结束 / 截图落盘时显式调用 `ExperienceHistoryService.invalidateCache()`（现全库零调用） | 新会话 / 新截图立即反映到日历与概览 |
| E3 | 截图写盘拖慢游戏 | 卡顿 | 捕获与落盘异步；写盘失败重试且不阻塞；图片压缩与缩略图预生成 | 按热键期间游戏帧率无可感变化 |

## 6. 信息架构与界面

- `HomePage` 目前**没有**「打开专属界面」的对外回调（`:19-31`），装配点在 `main_container.dart:1355-1363`；若走组件自持 `context` 直接开对话框（如现有 `_showDetailSheet` `:648`），则**不必改稳定区** `main_container.dart`。这是推荐路径。

### 6.2 专属界面（D4 / D5）

建议形态：**一个近全屏的深色沉浸对话框**（`showAppDialog` 适合长时间存活；深色体系可复用
`game_detail/dark_surface.dart` 的 `DarkPalette` 与 `showDarkCenteredDialog` 的转场），
进入时是一次明确的"空间切换"，退出回到原处（主页 / 详情弹窗）。

```
┌─ 游玩记录簿（沉浸层）─────────────────────────────────────┐
│  [全局概览]  [单游戏记录簿]        ← 两个视图，切换不换窗口   │
│ ─────────────────────────────────────────────────────── │
│  当前上下文：全部游戏 / 某款游戏（由入口决定）                │
│                                                          │
│  视图 A 全局：一段主视觉（年度/全局轨迹） + 状态分布 + 概览数字  │
│  视图 B 单游戏：作品头图 → 时间线 → 会话卡 → 截图流 → 里程碑   │
│                                                          │
│  常驻：搜索/年份切换（轻） · 导入已有截图 · 导出回忆册（建议）   │
└──────────────────────────────────────────────────────────┘
```

「像一款简单的小游戏」怎么落地（D9），**具体到可验收**：
- **收集感**：截图收藏册、里程碑徽章、按年份的"图鉴页"；收集对象是回忆，不是分数。
- **即时反馈**：截图成功的轻动效 + 可选快门音；本次游玩小结是一张卡片而不是一行日志。
- **零失败**：没有倒计时、没有分数、没有任务、没有"完成度"压力；跳过不等于失败。
- **成就感来自回看**：「原来那年我玩了这些」的完整册页，而不是积分数字。
- **三次点击原则**：从入口到任何一张具体的图 / 一段文字，不超过 3 次点击。
- 明确排除：签到、任务列表、成就进度条、排行榜、弹窗催促（§2 非目标）。

### 6.3 主页折线图改造（D7 / D10，开发重点）

不改几何位置（底部已满），改**角色与内容**：

1. 从"角落浮层"变成"主页代表功能"：标题从时段统计改为「我的游玩记录」语义，
   保留 7/30/90/全部胶囊与折线，但折线上**标出有故事的日子**（有截图 / 有文字 / 有状态变更的日子用可点标记）。
2. 折线图本身承担**入口**：点某个有标记的点 → 直接带日期进入记录簿并定位到那天；
   面板的「详情」链接 → 进入全局概览。
3. 中部 `Spacer()` 空白（`home_page.dart:548`，约 240px 高 / 830 宽，目前完全未被占用）
   建议放一张**低干扰的「最近一段回忆」卡片**：最近一次游玩的作品、时长、一张缩略图、一句可跳过的话；
   无数据时自动隐藏，不占空态。这是让主页"有代表功能"而不破坏现有布局的最小做法。
4. 收起态仍是 260×28 一行，展开态 320×196 不变（`play_stats_panel.dart:341-342,392-393`），
   `AnimatedSize(alignment: bottomRight)` 不动。
5. 可复用件：折线图 `:755-915`、时段胶囊 `:488-527`、图标按钮 `:530-568`、
   日历锚定 `:574-604`、明细弹层 `:647-751`、容器 `:918-947`。唯一外部调用点 `home_page.dart:565`。

### 6.4 状态视觉化（D10）

- 状态不再是 4 选 1 的文字下拉，而是**时间轴上的节点**：
  未入坑 → 游玩中 →（已通关 / 已弃坑）→ 可能再回到游玩中。
- 桌面与大屏文案目前不一致（`dropped` 桌面「已弃坑」、大屏「搁置」），
  建议**统一文案**或至少在记录簿内统一，避免玩家以为是两种状态。
- 全局概览用**状态分布**替代单纯数字：一款游戏一个位置，颜色/图形表示当前状态，
  点击直接进该游戏记录簿（顺手解决"日历点进去不能跳游戏"的旧问题）。
- 通关 / 弃坑作为**里程碑**展示（带日期、可附感想），不是当前值的标签。

## 7. 功能规格（逐项）

### 7.1 专属截图（D2 / D3）

| 环节 | 规格 |
|---|---|
| 触发 | 一个可配置的全局热键；**应用未聚焦时也要响应**（这是与现有 F11 应用内快捷键的本质区别） |
| 归属 | 前台活跃会话 > 唯一活跃会话 > 最近确认会话；不确定 → 「待归属」收件箱，玩家事后一键归位 |
| 存储 | 建议独立用户资产根，按 `game_id` 分目录、按年月分层；**与 `screenshots/` 完全隔离** |
| 索引 | 一条记录含：图片相对路径、`game_id`、`session_id`（可空）、捕获时间、来源（热键/导入）、私密标记、可选一句话 |
| 反馈 | 不改焦点的轻提示；成功/失败都要有；失败给出可读原因 + 补救路径 |
| 补充入口 | 「导入已有截图」：选文件 → 归到游戏 / 日期（默认读文件时间）→ 标注「导入」 |
| 内容保护 | 显式 `enqueueFile` 进 NSFW 管线 + 用 `NsfwImage` 渲染；支持「私密」标记；不上传云端 |
| 边界 | 无活跃会话、多会话、提权窗口、全屏独占、多显示器、热键被占用、磁盘写入失败，逐项见 §5 B 组与 §9 |

### 7.2 会话手记（D1）

- 每条会话自动成一张卡：起止时间、本次时长、当时的截图、这次是第几次、退出原因（正常 / 崩溃 / 手动结束）。
- 一张卡上只有**一个可选的一行输入框**，用于吐槽；不保存不产生空卡。
- 支持后补与编辑，后补标注「后补于…」。
- **注意**：`SessionRecord.fromJson` 目前只解析 3 个字段、`aggregateSessionsToDaily` 会过滤 <60s，
  所以手记索引必须**独立于聚合链路**保存，不能塞进 sessions 后指望聚合层带出来。

### 7.3 状态里程碑（C4 / C5 / D5）

- 状态变更记成事件：`from / to / at / note(可选) / 来源(手动|自动)`。
- `not_started → in_progress` 由启动链路自动记（现有 5 处自动流转保持不变）。
- `completed / dropped` 走专门的「落章」交互：确认 + 可选感想 + 生成一张可回看的回忆卡。
- 通关/弃坑后再次启动：轻问「又捡起来了？」，可一键回到游玩中，也可保持原状态。
- 状态事件**能编辑 / 删除**，保留历史而非覆盖。

### 7.4 单游戏记录簿（D5）

- 头部：作品、当前状态、首次 / 最后一次、累计时长、总次数、截图数、里程碑。
- 主体：时间线（默认按月聚合，点开到逐次会话）；会话卡内含截图缩略流与文字。
- 尾部：「最后一次」封底感 —— 让玩家看到"这段经历到这里"。
- 空态：即使什么都没写，也用自动数据撑起一屏（D1 / D4 判据）。

### 7.5 全局概览（D5）

- 已有可直接用：累计总时长、总次数、游玩中/已通关数（`big_picture_home.dart:185-190`）、
  按月活跃天数（`MonthSummary.activeDayCount`）。
- 需新算：累计游玩天数、连续天数（streak）、平均时长、**历史**通关数（按事件而非当前值）。
- 呈现：一段主视觉轨迹（年度/全局）+ 状态分布图 + 少量数字；数字不是主角。
- 口径统一是前置条件（§5 D4 / 调研报告 §5），否则"全局概览"会把不一致放大成一屏。

### 7.6 回忆完整性清单（D11，终极目标）

| 要能回答 | 数据来源 | 现状 |
|---|---|---|
| 曾经什么时候玩过、那次玩了多久 | `sessions` + `sessions_archive.json` | 已有（但只在图表里聚合，无逐次列表） |
| 那次留下了什么画面 | 新增过程截图索引 | 缺 |
| 那次我说了什么 | 新增会话手记 | 缺 |
| 什么时候通关 / 弃坑、当时怎么想 | 新增状态事件 | 缺（连时间戳都没有） |
| 一共玩了多少、跨度多长 | 统计聚合 + 新算指标 | 部分 |
| 退坑后还能不能找回来 | 资产落点 + 导出 + 不误删 | **需专门决策（§8 / §9）** |
| 以前（本功能上线前）的经历 | `sessions` 历史导入 + 后补 / 导入截图 | 需提供补录路径 |

> 完整性还包括**可携带**：建议提供「回忆册导出」（图片 + JSON + 一份可直接看的 HTML/图片页），
> 让记录不锁死在本软件里。这与"个人资产"的定义一致。

## 8. 数据设计（建议方案，待拍板）

### 8.1 落点决策表（这条决定"资产会不会丢"）

| 落点 | 会被归档 `appdata.7z` 打包 | 还原时被旧快照覆盖 | 删游戏时 | 建议 |
|---|---|---|---|---|
| `<metaDataDir>/`（`game.json` / `screenshots/` 同级） | 会（排除清单只有 `.ctgame` 与 `saves`；`game_archive_service.dart:198-199,383`） | 会（`:895-899`，只有 `game.json` 被特殊保护 `:880-912`） | **递归整个目录删除**（`local_game_registry.dart:2221-2224`） | **不建议**放用户资产 |
| `PathHelper.dataDir` 下独立根 | 不会（不在归档源根 `:329`） | 不会 | 不会被删（需自行按 `game_id` 清理孤儿） | **建议** |

**建议（待用户拍板）**：
- 用户资产与记录索引放在 `data/` 下的独立根，按 `game_id`（ADR-011 稳定主键）分组，
  **不碰 `game.json`、不动 `format_version=4`**。
- 参照现成写法：`PatchVaultData`（`data/patch_vault/index.json`，按 gameId 分组、零 schema 迁移、
  `.tmp → .bak → rename` 原子写、`patch_vault_index.dart:10-15`）与
  `WebsiteEntry`（`data/websites.json`，note + 时间戳 + ChangeNotifier）。
- 好处：绕开 ADR-012 迁移链、`_overwritableFields` 覆盖黑名单、`GameJsonData.toJson` 全量回写、
  元数据刷新误伤、归档还原覆盖、删游戏误删这一整串坑。
- 代价（必须配套解决）：不进 `appdata.7z` → 需要独立的「备份 / 导出回忆册」；
  删游戏后数据留存 → 需要明确的「保留 / 一并删除」询问，且默认保留。

### 8.2 实体草案（示意，非定稿）

```
data/play_journal/
  index.json                 → { version, games: { <game_id>: { sessions, milestones, moments } } }
  moments/<game_id>/<yyyy-mm>/
    <timestamp>_<short>.webp → 图片本体（与 screenshots/ 彻底隔离）
  export/                    → 回忆册导出产物（建议）
```

单条 moment（截图 / 手记共用索引）：
`id, gameId, sessionId?, capturedAt, source(hotkey|import), file?, text?, private, note?, createdAt, backfilled?`

单条 milestone：`id, gameId, from, to, at, note?, origin(manual|auto)`

会话手记引用 `session_id`（`_GameSession.toSessionRecord()` 已生成 UUID，
`local_game_registry.dart:155,199`），归档裁剪后 `sessions_archive.json` 仍保留完整记录，可以对齐。

### 8.3 与既有机制的关系（必须遵守）

- **不改 `game.json` 结构**（建议），因此 `GameJsonData` / `_overwritableFields` / 迁移链都不用动。
- **`onGameSessionEnded` 是单一回调字段、只有 2 个参数**（`gameTitle, sessionSeconds`），
  且**已被 TrayService 占用**（`local_game_registry.dart:2549`、`tray_service.dart:69-75`；
  `running_tasks_service.dart:105-107` 明确警告覆盖会静默破坏托盘通知）。
  新功能要感知会话结束，**必须**走链式保存 `previous`（`gamepad_adaptation_coordinator.dart:254-269` 是现成范例）
  或新增独立通知机制，**不能直接赋值**。误启动（<60s）分支不触发该回调（`:3534-3551`），
  若要把短会话也记进回忆，需另外接入。
- UI 感知走 `LocalGameRegistry` 的 ChangeNotifier（`play_stats_panel.dart:69` 已是范例），
  并在会话结束 / 截图落盘时显式调用 `ExperienceHistoryService.invalidateCache()`（现全库零调用）。
- `_notifyPlayTimeUpdate()` 不失效索引、只 `notifyListeners()`（`:522-525`），
  新增聚合索引要自己决定失效时机。
