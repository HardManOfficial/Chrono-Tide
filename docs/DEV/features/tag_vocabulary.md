## 1. 问题定义（实机反馈）

库页标签来自**多源翻译**（`luna_metadata_sdk/lib/services/tag_translator.dart`：VNDB 英→中
≈5800 条 / 内置英中日映射 ≈1141 条，去重后约 **6687 个中文标签**），玩家还可自由增删
（`LocalGameRegistry.setGameTag`）。而原「标签库」只有手写 `tag_taxonomy.json` 的 **9 个标签**
（题材 5 + 体验 4），且标签平铺无维度、过滤为精确字符串比对
（`library_page.dart` 的 `tags.any(t.trim()==tag)`）。三类后果：

| 问题 | 表现 |
|---|---|
| 分类非自动 | 展示的是预置 9 条，而非按库内数据归纳 |
| 无维度体系 | 无法按 年龄/玩法/舞台/基调/情感/元素/角色/美术 检索 |
| 同义 + 边界混乱 | 同一含义多写法（纯爱/純愛/Vanilla）各占一项；一个标签可能属多个大类 |

## 2. 方案总览

三层架构（见 `category_box.md` 架构说明）：

```
库内自由文本标签 → 归一化 + 别名倒排解析 → 规范概念（唯一维度） → 自动派生视图
                                          ↘ 未命中 → 未归类桶
```

**数据模型（两份随包只读 asset）**

- `tag_dimensions.json`：维度注册表 `{id, title, order, exclusive, color, desc}`，
  共 **9 维**：年龄分级 / 玩法结构 / 世界观舞台 / 作品基调 / 主旨情感 / 剧情元素 /
  角色特征 / 美术音频 / 成人内容。
- `tag_vocabulary.json`：受控词表 `concepts[] {id, name(规范名), dim(唯一维度), aliases[]}`。
  **当前 688 概念 / 5253 别名键**（生成器内置基表 97，其余由生成期吸收 VNDB/NextMoe 语料）。

**关键约束（攻克两个核心问题）**

1. **同义别名**：归一化（trim → 全角转半角 → 小写 → 去标点空白）+ 别名倒排索引
   `normalized(规范名|别名) → 概念id`，**多对一收敛**；别名键冲突时**先到先得**。
2. **大类边界重叠**：**一个概念只属于一个维度**（单维度归属）；维度之间**正交**
   （可同时叠加不同维度的条件）；归一化后**跨概念别名冲突数必须为 0**（有测试守护）。
   - 裁决实例：`巫女` 归「角色特征·巫女」而非「和风舞台」；`学生` 归「角色特征·学生」；
     `无口/天然` 按产品决策归「剧情元素」。
3. **保守不做模糊匹配**：宁可漏匹配进「未归类」，也不错合并两个不同含义
   （呼应 ADR-007）。语料扩展只接受「人工基名 + 安全后缀（女主角/主人公/系/娘…）」且
   排除否定词（无/非/不/未），已在生成阶段剔除「恐怖主义→恐怖」「冒险者→ADV」等噪声。

**自动派生**：`TagVocabularyStore.derive` 遍历库内游戏标签，按概念聚合计数；标签库**只展示
计数 > 0 的概念**，**0 成员的维度/概念自动隐藏**——分类来自库数据，而非预置清单。

**过滤语义：维度内并集 · 维度间交集**（用户拍板）
- 同一维度多选 → 任一命中（并集）；
- 不同维度之间 → 都要命中（交集，实现「组合偏好」的收窄检索）；
- 未命中词表的标签作为独立的「其他」分区参与（组内并集、与维度组取交集）。

**UI**：标签库分区标题 = 维度名（顺序 + 维度主题色圆点），概念 chip 沿用原 Wrap +
`IntrinsicWidth`（窄栏安全）；末尾「其他」分区（计数降序，封顶 80）。
拖卡片到概念 chip = 把该概念的**规范名**写进游戏标签（收敛用户数据到词表）。
