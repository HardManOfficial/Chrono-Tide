## 0. 结论先行

1. **误判与漏判不是同一个原因，不能靠单一阈值解决。**
   - **误判**主因：判定只有「单分数 + 单一硬阈值 0.648」，模型分数被压缩在 0.65–0.88 的窄带内，低分端（0.65–0.72）混入明确健全图。
   - **漏判**主因：判定维度被前几版迭代**逐个砍掉**（v2.2.1 复核门被评「只砍召回」而删、v2.3 删 applyR18Gate、`sensitive` 类被并入健全侧）——当前**没有任何二次信号**，凡是主分类器漏掉的样本永不补救。
2. **高分端（≥0.85）可信**：63 条目视全部为真裸露。**问题集中在 0.65–0.82 的「灰带」**（占全部判定 53%）。
3. **探索库数据问题的实质是「覆盖不足」而非「判定错误」**：缓存仅 1358 条（上限 5000），探索库 PB 封面只按需检测、未全量扫描，且其图源多为 eroge 封面（本身就擦边），所以观感上「误判漏判都多」。
4. **建议方向**：把「单阈值」升级为「**分级判定 + 类别感知 + 可调强度档位 + 灰带复核**」，并把探索库纳入分级策略。全部改动**可回滚、可灰度**。

## 3. 优化方案

### 3.1 取舍原则与可接受边界

**核心取舍：误判（FP）与漏判（FN）非对称 —— 漏判代价 >> 误判代价。**

| 类别 | 定义 | 可接受边界 | 理由 |
|---|---|---|---|
| **P0 漏判** | 露点/下体/明确性行为被放行 | **0 容忍** | 功能安全底线；用户明确点名 |
| **P1 误判** | 明确健全图被模糊 | 目标 <2%，允许有「可一键揭示/申诉」的出口 | 有 `allowReveal` 兜底，代价可恢复 |
| **P2 灰带** | 泳装/内衣/性暗示姿势 | **允许模糊**（判为敏感侧），但需分级提示 | 用户既定标准「性感擦边=健全」，但擦边封面模糊无伤大雅 |

**分级定义（建议新增）**：
- `pass`（< 低阈值）：健全，原样显示。
- `suspect`（低阈值 ≤ score < 高阈值）：**灰带** —— 默认模糊，**但标记为「疑似」并在揭示入口给出一键放行**（可回滚），可选只做弱处理。
- `blocked`（≥ 高阈值）：明确敏感，整图模糊，不提供快捷放行或需二次确认。

### 3.2 强度控制：从「单阈值」到「强度档位 + 双阈值」

**改动点**（`nsfw_settings.dart` + `nsfw_rating_postprocess.dart`）：

1. **新增用户可见强度档位**（`NsfwStrictness` 枚举），映射到双阈值：

| 档位 | 低阈值(FP 放宽) | 高阈值(blocked) | 语义 |
|---|---|---|---|
| 宽松 | 0.75 | 0.85 | 只拦明确露点，容忍擦边 |
| 标准（默认） | 0.70 | 0.83 | 平衡 |
| 严格 | 0.648 | 0.80 | 宁误勿漏（当前行为附近） |

> 阈值取值基于 §1.2 实测分布 + §1.3 目视真值：0.85 以上全真敏感（可作严格档 blocked 基线偏高需回测），0.72 以下混误判（可作宽松档低阈）。

2. **判定输出从「合成框」扩展为「带分级的框」**：
   - 复用现有 `NsfwBox.conf` 存 score（已有，零 schema 变更）；
   - **label 字段复用类别**：`2`=而 suspect 级 → label 可区分（当前恒写 2，需约定新语义）。⚠️ 见 §5 兼容性。

3. **类别感知（利用被丢弃的 `sensitive`）**：
   - 当前 `score = P(q)+P(e)`，`P(s)`（内衣/泳装）被忽略。
   - 新增辅助信号 `P(e)`（explicit 单项）作为**强证据**：`P(e) ≥ 0.5` 时无视阈值直接 blocked（露点/明确性行为高度对应 explicit）。
   - `P(s)` 高但 `P(q)+P(e)` 低的图（泳装/内衣），在**严格档**纳入 suspect，**宽松档**放行。

### 3.3 漏判补救：「灰带复核 + 保底规则」

由于**没有第二模型**且不应引入大依赖，建议**轻量、可回滚**的三条保底：

1. **explicit 单项硬门（最高性价比）**：`P(e) ≥ 0.5 → blocked`，不参与阈值比较。直接针对 R2 的「露点漏拦」。
2. **灰带记录而非放行**：`suspect` 级仍模糊（fail-closed），但写入「待复核」标记；设置页提供「查看疑似清单」，用户可一键标记为健全（写回缓存，覆盖判定）。→ 误判有出口、漏判不漏。
3. **探索库补扫**：把探索库 PB 封面纳入 `startFullScan`（或独立「探索库扫描」），解决 R4 覆盖不足。⚠️ 需评估 587+ 张的推理成本（按 §1.2 吞吐，2 worker ≈ 60–120 张/秒 → 数秒）。

### 3.4 探索库专项策略

| 策略 | 说明 | 回滚 |
|---|---|---|
| 全量补扫探索库封面 | 复用 `NsfwScanService`，新增探索库 URL 来源 | 移除调用点 |
| 封面口径独立档位 | 探索库封面擦边密集，**默认比本地库更严一档**，或对封面类只做 blur 不做隐藏 | 在 `NsfwImage` 按 `contentKind` 分支 |
| 未判定封面 fail-closed**已实现** | 未判定 → 模糊预览（`nsfw_image.dart:18`），不可揭示 | 已存在，无需改 |
| URL key 命中率 | 双键写入已实现；补扫时确保 URL 键落库 | 已存在 |

### 3.5 分辨率一致性（针对 R5）

**统一送入模型的解码路径**：目前缩略图（`memCacheWidth:200/480`）与原图走不同解码尺寸。建议**在 `_decodeForInference` 前统一按原图比例渲染到 inferSize**（已是拉伸 384，但源像素已被降采样）——
- 保底做法：检测时**始终读原始文件**（当前已是 `File(job.filePath)` 原文件，不是缩略图 ✓）。
- 真正的问题在**网络图**：`ensureUrlDetection` 等待 `getFileStream` 落盘，落盘的是 `maxWidthDiskCache` 缩放版 → 送入的是缩略图。**需确认**缓存盘文件是否原始尺寸（待验证，见 §6 缺失信息）。

## 4. 每项调整的预期收益与副作用

| 调整 | 预期改善 | 副作用 | 风险等级 |
|---|---|---|---|
| 双阈值 + suspect 档 | 误判可被「灰带+可揭示」吸收，FP 观感下降 | 灰带仍模糊，用户仍需手动揭示 | 🟢 低 |

| 分辨率统一 | 相同图判定稳定 | 需改解码链路 | 🟡 中 |

## 5. 兼容性与可回滚设计

1. **缓存签名递增**：任何判定口径改动必须**递增 `modelSignature` 的 `rN`**（当前 r6 → r7）→ 整表作废重判，避免新旧口径混用（既有机制，`nsfw_settings.dart:112-129`）。
2. **档位持久化**：`NsfwStrictness` 存 prefs；**默认值 = 标准档**，与当前行为最接近，避免升级即变。
3. **分级语义兼容**：`NsfwBox.label` 当前恒为 2（占位）。若用 label 承载分级，需**确认无渲染层/测试依赖**（已查：渲染层不消费 label，`nsfw_rating_postprocess.dart:18-19`）；更稳妥是**新增可选字段 `tier`**，`fromJson` 缺省 → `blocked`（向后兼容）。
4. **可回滚**：所有新逻辑走开关/档位分支；一键回退 = 档位设回「严格执行旧阈值」或降级总开关。
5. **灰度**：先只改「explicit 硬门」（单一变量，可 A/B），再逐步上双阈值/类别感知。
6. **不影响无关功能**：改动集中在 `lib/services/nsfw/` 与 `lib/widgets/nsfw/`，**不碰稳定区**（main/theme/portable_*/app_state）。

## 9. ✅ M4 实测结果（2026-10-15，Task #1 完成）

> 探针：`dev_probe/nsfw_m4/probe_m4.py`（Python ctypes 直调 `onnxruntime.dll` C API，绕过 Flutter/Dart 工具链）。
> 样本：70 张分层抽样（39 = 旧系统判定 flag，31 = 未判定/clean），384×384 RGB 送入模型，输出 4 类原始 softmax。
> 产物：`dev_probe/nsfw_m4/probs.jsonl`、`m4_explicit_montage.png`、`m4_questionable_montage.png`。

### 9.1 核心结论：P(explicit) 是干净的强判别器 ✅

| 组 | P(general) | P(sensitive) | P(questionable) | **P(explicit)** |
|---|---|---|---|---|
| flag 组（n=39） | — | 0.059–0.322 | 0.054–0.729 | **0.066–0.820** |
| clean 组（n=31） | — | 0.250–0.720 | 0.067–0.470 | **0.063–0.212** |

**关键隔离带**：clean 组 P(e) 最大值 = **0.212**，flag 组中明确露点子集 P(e) 最小值 = **0.533**。
⇒ 0.21 ~ 0.53 之间是**无人区**，阈值取中点偏保守的 **0.5** 极安全。

### 9.2 目视确认（montage 双图）

- **`P(e)≥0.5` 组（n=16）**：**全部为真露点/明确性行为**（全裸、性器外露、性交 CG）→ 硬拦零误伤。
- **`P(e)<0.5` 且 qe≥0.648 组（n=23）**：eroge 封面 / CG 画廊 / 擦边立绘；含若干**疑似 FP**（如 015/016/017 的纯恋爱向角色封面）→ 这正是需要「软处理 + 可复核」的群体。

### 9.3 对方案的定阈影响

- `explicitThresh = 0.5`（**实测确定**，不再是暂定值）。
- 三分层经数据验证成立：
  - `explicit`（P(e)≥0.5，n=16）→ 硬拦；命中率 100% 真阳，零 FN 风险。
