## 1. 目标：解决什么问题

后台模型数据已完成变更，但视图不会自动响应更新；必须依赖用户手动操作
（点击、滚动、页面跳转）触发组件重建后，界面才展示最新状态。

**审计结论（2026-09-07 只读审计）**：视图层监听与重建机制本身健全——
库页/主页/BPM 都正确监听 `LocalGameRegistry`（ChangeNotifier），横幅用
`AnimatedBuilder` 监听 `RunningTasksService`，NSFW 渲染链路有 store+settings
双监听与差异化重建。**总根因是大量「改数据」的代码路径只写磁盘 / 只改弹窗
局部状态：既不更新 `LocalGameRegistry._games` 内存对象，也不发通知。**
通知一旦发出，全链路自动刷新。

## 2. 修复设计：关键取舍

| 决策点 | 选择 | 原因（含被否决方案） |
|--------|------|----------------------|
| 整体方案 | **补通知 + 同步内存**（复用既有 ChangeNotifier 链） | 监听端全部健全，缺的只是「通知没发出来」。被否决：引入 Provider/Riverpod 全量重构（改动面巨大、违背最小变更、外观行为全变） |
| 通知语义 | 复用 `RegistryChangeReason.structural`（UX-34 既有机制） | 库页/主页/BPM 对 structural 已有正确的轻量处理（重排列表，非全盘 scan）；不新增语义 = 监听端零改动 |
| 启动链路通知 | 用 `playTimeUpdate` 而非 `structural` | 启动是相对高频操作，playTimeUpdate 语义更轻（库页/主页仅 setState，不清封面缓存、不重排序） |
| 封面缓存失效 | 通知端清 `_coverPathCache`（库页对齐主页既有行为） | structural 是低频事件；清缓存后由 `_applyCustomOrder → _resolveAllCoverPaths` 自动重解析 |
| 同名覆盖封面 | `_evictCoverImageCache`：FileImage 基键精准 evict + `imageCache.clear()` 保底 | ImageCache 以「文件路径」为解码缓存键，同名覆盖（手动换封面固定存 cover.png）会命中旧位图；ResizeImage 键无法枚举宽度，clear() 是唯一可靠兜底。换封面低频，可见图一次性重解码成本可接受 |
| 编辑保存同步内存 | `getGameByTitle` 拿内存对象直接回写字段 | 与 `screenshot_fetch_service.dart:372-388` `_refreshRegistry` 既有模式一致（项目内正确范本） |

## 4. 重点场景与验证方式

所有场景的统一自测方法：**修改后台数据后，不做任何手动界面操作，观察 UI 是否自动更新**。

| 场景 | 操作 | 期望 |
|------|------|------|
| 元数据修改 | 详情弹窗编辑描述/标签/会社/副标题 → 保存 | 库页/主页卡片即刻显示新值（无需滚动/切页） |
| 封面替换（手动） | 详情弹窗「点击更换封面」选本地图 | 弹窗与库页/主页列表封面同时刷新 |
| 封面替换（网络） | 详情弹窗抓取回填封面 | 同上 |
| 游玩状态（弹窗） | 详情弹窗修改游玩状态 | 库页徽标即刻变化 |
| 游玩状态（库页批量） | 库页多选 → 设置游玩状态 | 主页/BPM 徽标同步 |
| 游玩状态（启动） | 启动游戏（notStarted → inProgress） | 各页面「游玩中」徽标即时出现 |
| 星标 | 卡片/菜单切换星标 | 其他页面星标同步 |
| NSFW 判定完成 | 打开未判定截图/封面 | 模糊 → 判定完成自动清晰/打码（**本次未改动**，既有链路已响应式，v2.2.1 已验证） |
| 横幅状态 | 启动/退出游戏 | 横幅状态与计时实时跟随（**本次未改动**，AnimatedBuilder 已响应式） |

## 6. 已知边界与风险

1. **`imageCache.clear()` 的瞬时成本**：换封面瞬间可见图片一次性重新解码
   （毫秒级/张），可能有一次极轻微的整体刷新观感；低频操作可接受。
2. **ResizeImage 键残余**：`_evictCoverImageCache` 精准 evict FileImage 基键，
   经 `cacheWidth` 包装（库页卡片 480px）的解码键靠 clear() 兜底——两者合并
   已覆盖全部路径；若后续新增解码尺寸接入点，无需额外处理。
3. **同名覆盖之外的场景天然安全**：封面文件名变化（cover.png → cover.jpg）
   时 coverUrl 变化 → 全链路自动刷新，与缓存无关。
4. **信息不落通知**：`notifyDataChanged()` 不携带变更详情（哪个游戏/哪个字段），
   监听端按 structural 全量轻刷。如未来出现高频字段变更场景，可升级为
   携带 metaDataDir 的定向通知（当前无此需求，不做过度设计）。
