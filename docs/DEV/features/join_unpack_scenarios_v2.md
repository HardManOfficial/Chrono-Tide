## 1. 需求逐条评估：遗漏 / 冲突 / 风险

### 1.1 分卷压缩（需求 1）

**社区形态**（7z 23.01 / WinRAR 实测惯例）：

| 格式 | 分卷命名 | 解压入口 | 备注 |
|------|----------|----------|------|
| 7z | `file.7z.001/.002/...` | 喂 `.001`，7z 自动找同目录后续卷 | 首卷带 7z 魔数 |
| zip | `file.zip.001/...` 或 `file.z01/.z02/...+file.zip` | 喂 `.001` 或 `.zip`（后者为合并指示卷） | `.z01` 魔数 = spanned 标记 `PK\x07\x08`（已在魔数表） |
| rar | `file.part1.rar...partN.rar` 或 `file.rar/.r00/.r01/...` | 喂 `.part1.rar` 或 `file.rar` | 旧式 `.rNN` 的主卷是 `file.rar` |
| lz4 | `file.zip.lz4.001`（复合） | 先归并 lz4 分卷再剥壳 | 社区少见，P2 |

**方案要点**：
- **归并组识别**：按「文件名主干 + 卷序号模式」分组（`base.7z.NNN` / `base.zip.NNN` / `base.partN.rar` / `base.rNN`+`base.rar`），同目录内只归并同主干——防跨包误归并（`fileA.001` 与 `fileB.001` 不得混合）；
- **探测期**（buildPlan）：拖入任一分卷 → 定位同目录全组 → plan 第 0 层显示为单一逻辑层（「分卷 N 段 + 总体积」）；**缺卷检测**（序号断档）→ warnings 提示缺哪段；**非首卷拖入** → 自动定位首卷并把首卷作为层入口；
- **执行期**：只把首卷喂 7z（7z 自行找同目录卷——要求全组卷在同一目录，与用户「源文件所在文件夹解压」默认一致）；
- **缺卷/卷损坏**：走 Phase F 统一损坏弹窗（明确报「缺第 N 段」），支持挂起（用户补齐文件后「继续」）。

**风险**：
- ⚠️ 卷不齐时 7z 中途报错且已落部分垃圾 → 失败清理已有（_cleanupOnFailure），挂起恢复模式需先清层再重试；
- ⚠️ 分卷 + 嵌套复合（`base.zip.001` 解出 rar）→ 分卷层解出产物后走既有重扫续链，天然支持，无冲突；
- ⚠️ 与习惯记忆/预设的交互：signature 需含「卷组指纹」（主干名 + 卷数），否则同组不同名分卷命中不了习惯。

### 1.2 多文件歧义（需求 2）

**现状缺陷**（两处，都出在 `_scanForNestedArchive` extract_manager.dart:1178-1191）：
1. **非确定性**：`dir.list(followLinks: false)` 顺序不保证 → 多候选时「解第一个」的结果随文件系统枚举序漂移；
2. **只看顶层**：`entity is! File continue`（:1182）→ 解出 `folder/game.zip` 结构时**发现不了子目录里的嵌套包** → 误判「解压完成」，把 folder 当散文件搬走收尾。

**方案要点**：
- 扫描器重构：返回**候选列表**（顶层 + 子目录一层，排序确定性 byPath），每个候选带 {path, magicFormat, declaredExt, sizeBytes}；
- 候选数 ≥2 → 触发挂起（复用 waiting_for_input 状态机，交互对齐密码弹窗）→ **目标文件选择框**：列表展示候选（格式/体积/魔数判定），用户单选本体，其余标诱饵；
- **推荐策略引擎**（可配置、持久化进 unpack_settings.json 新键 `ambiguity_rules`）：
  - 默认规则 1「多数同后缀 + 唯一异类」：≥3 候选且恰一个后缀异类 → 推荐异类（如 4×.mp4 + 1×.mov → 推荐 .mov），展示推荐理由；
  - 数量接近（异类比 ≥ 1/3）或无后缀区分度 → **不推荐**（用户已明确）；
  - 可选增强（P2）：体积维度（诱饵常为等大占位视频）、魔数维度（唯一魔数命中的优先）；
  - 规则表数据结构：`[{id, name, matcher(多数后缀/异类/体积离群), priority, enabled}]`，预留 UI 扩展。
- **诱饵去向（待拍板）**：a) 随临时层清理删除（推荐——临时层本就是 _temp_layer_N，最终收尾只搬选中候选所在目录）；b) 保留在最终目录。默认推荐 a。
- **挂起可恢复**：选择框期间临时层保留；用户取消 → 走放弃路径清理（与密码弹窗放弃同构）。

### 1.3 游戏本体识别（需求 3）

**现状**：收尾判定 = 「重扫无嵌套压缩包」→ 搬目录收尾。孤 .exe（真 exe 无配套）会被当散文件搬走入库，产出坏游戏；SFX 自解压包（MZ 头内嵌 archive）魔数表不识别 → 同样收尾失败。

**方案要点**：
- **收尾前置判定**（重扫无嵌套包后、搬目录前）：
  - `GameLauncherDetector.detect(dir)` 命中 exe **且** 目录含「配套文件」（规则待拍板，默认建议：exe + ≥1 个子目录 或 exe + ≥2 个非 .txt/.url/.url 类说明文件）→ **判定本体，终止**（现状直达）；
  - 存在孤立 .exe（无配套）→ **不终止**：先 `7z t` 试解（SFX 探测）→ 可解 = 当压缩层继续（SFX 续链）；不可解 = 进入需求 4 的映射决策窗（把 .exe 当「未知后缀」处理，候选链自动尝试 zip/rar/7z/enc）→ 全败 → 「未找到游戏本体」弹窗（用户可选「仍以此收尾」或「取消解压」）；
  - 目录里既无 exe 也无嵌套包 → 「未找到本体」弹窗（同上）。
- **误判双向防护**：
  - 判早了（中层产物恰好有 exe+配套）→ 选择框语义兜底：本判定只在「重扫无嵌套包」后触发，中层若还有包会先被发现——冲突场景 = 本体与嵌套包共存（本体 + 一个诱饵 zip）→ 优先问用户（多候选挂起涵盖）；
  - 判晚了（已是本体但规则不满足）→ 「未找到本体」弹窗给「仍以此收尾」出口，永不死锁。
- ⚠️ 本体识别规则必须**可配置可解释**（弹窗展示判定理由），规则参数进 unpack_settings.json。

### 1.4 未知后缀映射（需求 4）

**现状**：执行期新层 `currentFormat = nestedSniff.format ?? _planFormatFromName(nested) ?? currentFormat`（:1144-1146）——魔数与名字双未命中时**沿用上一层格式硬解**，7z 必报错 → failed 全清。主方案 §4.5 声明的 `waiting_for_strategy` 暂停弹窗**从未实现**。

**方案要点**：
- **补落地 waiting_for_strategy**：双未命中 → 挂起弹「后缀映射决策窗」：展示该文件（后缀/体积/魔数结果「未识别」），三个动作：
  - **手动指定格式**（下拉：zip/rar/7z/enc/lz4/…）→ 按指定格式解；
  - **自动尝试**（用户已明确）：按该后缀的**候选链**依次试解压，每次尝试前清层（复用 _clearDirectory :1299，防错格式落垃圾——Phase 0 T3 实测教训），成功即续链；
  - **终止**（取消解压 → 清理）。
- **候选链默认表**（可配置持久化 unpack_settings.json 新键 `auto_try_chains`）：
  - `.mp4 → [zip, rar, enc, 7z]`；`.mov → [enc, zip, rar]`（用户给定顺序）；
  - 视频/音频/文本/程序类后缀同等处理：`.exe → [zip, rar, 7z, enc]`、`.txt → [zip, rar]`、`.mkv/.avi/.flv → [zip, rar, 7z]` 等全量默认表见 §4；
  - **enc 特殊规则**：.enc 试解需要密码——仅当本任务已有该层密码（用户填过/记忆库命中）才把 enc 纳入自动尝试，否则跳过（无密码的 enc 试解 100% 失败还白耗 2s KDF）；
  - 候选链耗尽 → 回落「未找到游戏本体 / 无法识别」弹窗（需求 3/5 闭环）。
- **决策记忆**：用户手动指定的映射 → 追加进映射表（复用 SuffixMapping，isDefault 由用户勾选）→ 下次同类后缀不再打断（社区自动化关键路径）。

### 1.5 交互总原则（需求 5）

**现状盘点**：

| 异常 | 现状 | 缺口 |
|------|------|------|
| 密码错误 | waiting_for_input 弹窗 ✅（queue→补输→重试） | 无 |
| 后缀映射未知 | **沿用旧格式硬解→失败** | waiting_for_strategy 补落地（§1.4） |
| 多文件歧义 | 非确定性选第一个 | 选择框（§1.2） |
| 文件损坏 | 抛 Exception → failed 全清，无弹窗 | 分类弹窗（下） |
| 格式不支持 | 同上（如 EncFormatException :1214 直抛） | 分类弹窗（下） |

**损坏弹窗分类**（7z/bz/enc 错误文案 → 分类器）：
- 缺卷（分卷序号断档）→「缺第 N 段，请补齐后继续」；
- CRC/数据损坏 →「包损坏」；
- 格式不支持 →「暂不支持该格式/算法」（含 enc 非 AES 算法、v1-v3）；
- 全部支持「继续重试 / 取消解压」两动作；取消 → 清理临时层与残留（_cleanupOnFailure 既有）。

**挂起态与生命周期的统一语义**（收尾风险核心）：
- 挂起 ≠ 失败：三种挂起（密码/多文件/映射决策）+ 缺卷挂起期间，`_temp_layer_N` 与 `_taskOwnedTempArchives` **必须保留**；
- 页面 dispose / 再拖入：钩子断开返回 null = 放弃 → 清理（join_controller.dart:171-181/:384-385 先例）；防重入复用 `_isAwaitingPlanConfirmation` 先例；
- **清理分层**（明确化，防误删）：a) 取消/放弃 → 清临时层 + 自建中间包（现状已有）；b) 失败（用户选取消）→ 同 a；c) 成功 → 清临时层保留产物（现状已有）；d) **挂起 → 什么都不清**（新语义，需在 cancel() 与 dispose 路径明确豁免）。

## 2. 递归死循环 / 状态恢复专项核查

## 4. 分阶段开发计划

**排序原则**：先修地基（声明未实现项 + 存量 bug），再按「社区频率 × 独立性」排功能。Phase A 是执行期一切交互的地基；B/C 在 A 后可并行；D/E 依赖 A；F 收口全交互语义。

| Phase | 内容 | 依赖 | 复杂度 | 验证方式 |
|-------|------|------|--------|----------|
| **A 底座（P0，最先）** | ① 扫描器重构：多候选列表（顶层+子目录一层、byPath 确定性排序、候选带格式/体积）；② 执行期决策钩子泛化 `onExtractDecision`（密码/策略/多文件/损坏统一请求-响应通道，旧 onPasswordNeeded 保留别名兼容）；③ `waiting_for_strategy` 补落地：双未命中 → 暂停弹窗（先只有「手动指定格式/终止」两个动作，自动尝试 Phase B 加） | 无 | 中 | 探针：多候选目录枚举确定性；模拟双未命中暂停；flutter test 弹窗接线 |
| **B 未知后缀自动尝试（P0，社区最高频）** | 需求 4 全量：默认候选链表 + 决策窗（手动/自动尝试/终止）+ 每候选失败清层 + enc 需密码联动 + 决策记忆回写映射表 + 同后缀去重 | A | 中 | 探针：候选链逐试清层无残留；enc 无密码跳过；映射回写持久化 |
| **C 分卷归并（P1，独立可并行）** | 需求 1 全量：探测期分组/缺卷检测/非首卷定位 + plan 逻辑层表示 + 执行期喂首卷 + signature 卷组指纹 | A（缺卷挂起用钩子；探测期部分无硬依赖可先行） | 中偏大 | 探针：四种分卷命名分组/缺卷断档/非首卷拖入；7z 喂首卷真实解压 |
| **D 多文件歧义（P1）** | 需求 2 全量：挂起选择框 + 推荐规则引擎（默认「多数+异类」，可配置持久化）+ 诱饵处理（待拍板项） | A | 中 | 探针：4+1 异类推荐/数量接近不推荐/取消清理；flutter test 弹窗 |
| **E 本体识别（P1）** | 需求 3 全量：收尾前置判定（detector+配套规则可配置）+ 孤 exe SFX 试解链 + 「未找到本体」弹窗（仍以此收尾/取消） | A、B | 中小 | 探针：exe+配套判定/孤 exe→SFX→续链/孤 exe 非 SFX→决策链 |
