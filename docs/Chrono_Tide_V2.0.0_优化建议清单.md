# Chrono Tide V2.0.0 优化建议清单（V2 · 按本地工具定位重排）

- **更新日期**：2026-08-29
- **定位前提**：本软件本质是**本地工具**，云端仅作润色与扩展；登录注册只是客户端连接 PocketBase 的中介节点，
  用于支撑云端游戏库、远程安装等能力，**不是强绑定账号体系**。
- **因此本版明确撤回**：邮箱验证码、注册邮箱验证、找回密码验证码、账号强绑定 等一切强制性账号要求。
- **重点转向**：服务器权限、账号凭证安全、云端数据完整性（尽量多列）。
- **硬编码策略**：按影响程度分级。普通且影响小的硬编码**不处理**；只处理会严重影响开发者的条目
  （尤其涉及服务器权限、账号安全）。
- **元数据平台 API**：已确认由开发者本人向官方申请且官方允许公开，**不做去硬编码改造**。
- 本清单只给结论与可执行动作，**不含代码实现**。

| 上一版结论 | 本版处理 | 原因 |

| 注册需邮箱验证 | **撤回** | 同上 |

## 二、P0 · 发布前必须清零（阻断上线）

### P0-1　云端 `games` 集合可被任意登录用户改写 → 供应链投毒

- **证据**：
  - `lib/services/install_stats_service.dart:146` — 客户端直接 PATCH 共享集合：
    `collection('games').update(gameId, body: {'installCount': ...})`
  - `lib/pages/game_detail_page.dart:455-462` — 任意登录用户对任意 `gameId` 执行
    `PATCH /api/collections/games/records/$gameId`，写入 `screenshots` 文件
  - `lib/models/game_model.dart:10` — `games` 记录含 **`downloadUrl`** 字段
- **影响范围**：全部云端用户 / 开发者服务器 / 开发者法律风险
- **风险**：只要 `games` 的 updateRule 允许登录用户写入（客户端代码已在这么用，说明规则过宽），
  任何注册账号都能把热门游戏的 `downloadUrl` 改成恶意压缩包地址。
  其他用户点"远程安装"即下载并解压攻击者控制的内容，
  再叠加客户端的 PowerShell 注入面与 `..` 路径穿越问题，可升级为**远程代码执行**。
  同时可往 `screenshots` 灌入任意图片，使开发者的服务器成为违规内容托管点。
- **结论（可执行）**：
  1. 在 PocketBase 后台收紧 `games` 的 **updateRule / 字段级权限**，
     `downloadUrl`、`status`、`title`、`coverUrl`、`installCount` 等字段仅允许管理员/受信任角色写入。
  2. `installCount` 的累加改为**服务端 hook 自增**，禁止客户端传值。
  3. `screenshots` 若必须开放用户投稿，改为写入独立的待审核集合，审核通过后再合并进 `games`；
     并限制单账号投稿频率与文件大小（服务端校验，不能只靠客户端 2MB 检查）。
  4. 对 `games` 记录的变更开启服务端审计日志，`downloadUrl` 变更需告警。

### P0-2　客户端硬编码 PocketBase 超级管理员凭据

- **证据**：`lib/modules/auth/auth_service.dart:26-27`（邮箱+密码明文拼接）、`:156-195`（换取 superuser token）
- **影响范围**：整个后端 / 全部用户数据 / 开发者
- **风险**：凭据随安装包分发，泄露**不可撤回**。superuser 拥有所有集合的读写删除权。
  混淆只是字符串拆分拼接，`strings` 或反编译即可还原。
- **结论（可执行）**：
  1. **立即轮换** PocketBase superuser 密码与邮箱（旧凭据视为已泄露）。
  2. **客户端永远不得持有 superuser 凭据**。把需要提权的操作（查用户、重置密码）下沉到服务端
     PocketBase hook，以服务端持有的凭据执行，客户端只调用该自定义接口。
  3. 检查服务端是否已因旧凭据产生异常操作记录。

### P0-3　找回密码流程在客户端用 superuser 直接改写任意用户密码（架构问题）

- **证据**：`lib/modules/auth/auth_service.dart:198-335`（查 userId）、`:336-437`（直接 PATCH 改密码）
- **影响范围**：全部用户账号 / 开发者
- **风险**：**本条不是"缺验证码"的问题，而是权限边界错误**——客户端拿到了本不该拿到的写权限。
  即便不动用户交互流程，攻击者仍可用泄露的 superuser token 重置任意账号。
- **结论（可执行，不增加任何用户操作负担）**：
  1. 与 P0-2 同步整改：重置密码逻辑移入服务端 hook，客户端仅提交「邮箱 + 新密码」。
  2. 服务端侧加**真实**速率限制（客户端 `_rateLimitMap` 是内存级，重启/换设备即失效，不能作为防线）。
  3. 统一错误文案，避免邮箱存在性泄漏（客户端已做，服务端需保持一致）。
  4. 记录重置操作审计日志，短时内多账号重置触发告警。
  5. **不引入邮箱验证码、不强制二次验证**，保持"轻量账号"定位。

### P0-4　全部后端通信明文 HTTP

- **证据**：`lib/core/pb_config.dart:7` — `http://117.72.115.30:8090`
- **影响范围**：全部用户账号与数据 / 开发者
- **风险**：登录密码、token、superuser 凭据、用户资料全程明文，链路可被窃听与重放。
- **结论（可执行）**：
  1. 为 PocketBase 与更新服务（`:8000`）接入 HTTPS 证书，客户端切到 `https://`。
  2. 证书配置自动续期，避免到期后客户端集体失联。
  3. 服务端保留 HTTP→HTTPS 重定向，兼容已发布的旧版本客户端。

### P0-5　自动更新无完整性校验且直接执行下载的 exe

- **证据**：`lib/services/update/update_service.dart:24, 755-771`；
  `lib/services/update/update_models.dart:2-19`（`VersionInfo` 无 hash / signature 字段）
- **影响范围**：**全量在线用户** / 开发者
- **风险**：攻击者控制 `117.72.115.30:8000` 或劫持链路，即可让所有客户端下载并执行任意程序。
- **结论（可执行）**：
  1. `version.json` 增加安装包 SHA-256 字段，客户端下载后**校验通过才允许执行**。
  2. 有条件时对安装包做代码签名，校验签名链。
  3. `downloadUrl` 限定为 HTTPS，且服务端限制为固定域名/目录，防止指向外部地址。
  4. 更新服务器纳入运维管控与变更告警。

### P0-6　OpenList 配置包远程下发、无完整性校验、解压后直接作为配置启动

- **证据**：`lib/services/openlist_service.dart:94-195`（明文拉 `data.zip` → 解压）、
  `:977-1008`（`--config` 启动 `openlist.exe`）
- **影响范围**：全部在线用户 / 开发者服务器
- **风险**：服务端或中间人篡改 `openlist_configs` 的 `dataZip`，即可远程下发并生效一份恶意配置，
  等同后门通道。
- **结论（可执行）**：
  1. `data.zip` 提供哈希并在客户端校验，校验失败不解压、不启动。
  2. 下载与校验走 HTTPS（随 P0-4 一并解决）。
  3. 服务端对 `openlist_configs` 记录开启变更审计与告警。

## 三、P1 · 上线前应完成（不阻断但强烈建议）

### P1-1　云端 `games` 搜索 filter 注入

- **证据**：`lib/repositories/game_repository.dart:51` 与 `:250` —
  `final filter = "title ~ '$searchQuery'";`（用户输入直接拼接，无转义）
- **影响范围**：服务端数据 / 全部用户
- **风险**：可构造布尔盲注条件探测集合中其他字段（含关联用户字段）的取值；也可使查询报错。
- **结论**：服务端对 filter 入参做白名单与长度限制；客户端对 `'` 与 `\` 做转义（先转义 `\` 再转义 `'`）。
  `install_stats_service.dart:183` 的 `_escape` 只处理 `'`，需一并修正。

### P1-2　安装统计去重键由客户端提供，可任意刷量

- **证据**：`lib/services/install_stats_service.dart:83-90`（`userName` 取本地缓存后提交）、
  `:124-131`（以 `gameId + userName` 查重）、`:37-41`（代码注释自述"建议配置 UNIQUE 索引"）
- **影响范围**：服务端统计口径 / 开发者运营数据
- **风险**：用户改一次昵称即可为同一游戏重复计数；也可冒用他人昵称制造虚假记录。
- **结论**：服务端为 `install_records` 建立 `(gameId, userId)` 唯一索引，
  改用服务端可信的 `userId` 而非客户端昵称作为归属键；`gameTitle` 由服务端按 `gameId` 回填。

### P1-3　注册与资料更新的字段级权限待确认

- **证据**：`lib/modules/auth/auth_service.dart:655-662`（注册仅提交 email/password/name）、
  `:973-976`（更新仅提交 name/description）
- **影响范围**：服务端账号体系
- **风险**：客户端本身没有越权字段，但需确认服务端是否限制了字段级写入。
  若 `users` 集合的 create/update 未限制字段，攻击者可绕过客户端直接提交
  `verified`、`emailVisibility` 或任何自定义字段。
- **结论**：在 PocketBase 后台为 `users` 配置字段级 create/update 权限，
  仅开放 `name` / `description` / `avatar`，其余字段仅管理员可写。

### P1-4　本地数据丢失类缺陷（沿用上一版结论，优先级维持）

- `game_data_format.dart:107-168` — `writeGameDir` 整包覆盖已有 `game.json`，重复安装即清零游玩时长
- `collection_service.dart:157-162` — 加载失败即清空并覆写磁盘，收藏夹永久丢失
- `collection_service.dart:235-254` — 多入口并发写同一 `.tmp`，无串行化
- `storage/migration_orchestrator.dart:164-170` — 不校验内容即删除旧数据
- `local_game_registry.dart:1194-1208` — 删除游戏连带删除存档备份（**建议先确认是否为有意设计**，
  若是，至少在 UI 明确告知"将同时删除存档备份"）
- **影响范围**：用户本地数据（不可恢复）
- **结论**：发布前逐项修复；这些都是本地工具的核心资产，比云端功能的优先级更高。

### P1-5　可稳定复现的崩溃与界面锁死（沿用上一版结论）

- `library_page.dart:1096` — 过滤态下拖拽必崩（RangeError）
- `extract_manager.dart:1987-2005` + `join_controller.dart:303-309` — 取消入库后遮罩永不消失
- `game_detail_dialog.dart:425-449` — Magpie 失败时弹窗不可关闭
- `batch_import_controller.dart:636-650` — 删除批量任务时删掉用户磁盘原图
- **影响范围**：全部用户，日常操作高频命中
- **结论**：发布前逐项修复并回归验证。

## 四、P2 · 建议排期处理

### P2-1　登录凭据明文持久化在便携目录

- **证据**：`lib/modules/auth/auth_service.dart:941-950`（token 写入 SharedPreferences）；
  便携存储路径 `PathHelper.prefsFilePath` = `{exeDir}/data/prefs/shared_preferences.json`
- **影响范围**：用户账号
- **风险**：便携版用户常整目录拷贝、备份或分享，长期有效的 token 会随之流转；
  叠加明文 HTTP 可被链路重放。
- **结论**：缩短 token 有效期、退出与换机时主动吊销；
  持久化优先使用系统凭据存储（Windows Credential Manager），退而求其次做本地加密后再落盘。

### P2-2　服务端无任何速率限制与审计

- **证据**：`lib/modules/auth/auth_service.dart:40-63`（限制为客户端内存级 `Map`）
- **影响范围**：服务端账号与数据
- **风险**：客户端限制重启即失效、换设备即失效、多开即失效，无法对抗爆破、枚举与刷量；
  且服务端无审计日志，事后无法溯源。
- **结论**：服务端对登录、注册、找回密码、安装上报、内容投稿分别加限流；
  对密码重置、`games` 记录变更、`installCount` 异常增长开启审计与告警。

### P2-3　昵称查邮箱存在批量枚举面

- **证据**：`lib/modules/auth/auth_service.dart:504-570`（`lookupEmailByName` 模糊查询返回脱敏邮箱）
- **影响范围**：全部用户隐私
- **风险**：60 秒限制同样只在客户端内存，可被批量枚举"昵称 → 邮箱前后缀"映射，
  与 P0-3 组合后会显著提升账号接管成功率。
- **结论**：限流下沉到服务端并按 IP + 账号维度；对返回脱敏邮箱的接口单独设更严格的配额。

### P2-4　头像与截图上传缺少服务端校验

- **证据**：`lib/widgets/settings_modal.dart:4006-4019`（仅客户端校验扩展名与 2MB）；
  `lib/pages/game_detail_page.dart:455-470`（截图直传 `games`）
- **影响范围**：开发者服务器
- **风险**：客户端校验可绕过，服务器可能被当作任意文件托管点。
- **结论**：服务端校验文件类型、尺寸与内容魔数；限制单账号存储配额与投稿频率。

### P2-5　OpenList 本地服务使用硬编码 admin/admin

- **证据**：`lib/services/openlist_service.dart:1054-1060`
- **影响范围**：本机（监听 127.0.0.1:5244）
- **风险**：凭据固定且已知，本机任意进程、DNS rebinding 或浏览器侧请求都可能被利用；
  与 P0-6 的配置注入叠加后危害放大。
- **结论**：首次启动时随机生成管理员密码并写入本地配置；如可行，改为仅监听回环并校验 Host 头。

### P2-6　解压与计算的稳定性问题（沿用上一版结论）

- `foreground_window_service.dart:127-136` — FFI 失败时同步拉起 PowerShell，UI 冻结
- `local_game_registry.dart:2889-2927` + `save_scanner.dart` — 存档扫描全同步遍历，大目录卡顿
- `local_game_registry.dart:2244-2251` — `clamp(0, 4)` 导致时长系统性少计
- `local_game_registry.dart:498-513` — 移动硬盘未就绪时游戏被静默移出库
- **影响范围**：全部用户，本地核心体验
- **结论**：作为本地工具的稳定性项，建议在 P0/P1 之后集中处理。

## 七、建议执行顺序

1. **第一步（立刻，不等发版流程）**：轮换 superuser 凭据并排查已泄露影响 —— P0-2。
   这一项的泄露是**不可撤回**的，优先级高于一切。
2. **第二步（发版阻断项）**：P0-1 服务端集合权限整改 → P0-3 重置密码下沉服务端 →
   P0-4 全站 HTTPS → P0-5 更新包校验 → P0-6 OpenList 配置校验。
3. **第三步（发版阻断项）**：P1-4 本地数据丢失 + P1-5 崩溃与锁死。
   本地工具的立身之本是数据不丢、不崩，这两组与云端安全同等重要。
4. **第四步**：P1-1 ~ P1-3 服务端数据完整性与权限收口。
5. **第五步**：P2 凭据存储、限流审计、本地稳定性。
6. **第六步**：P3 日志脱敏与 UI 细节。

> **一句话结论**：这一版要动的主要不是"账号流程"，而是"服务端权限边界"。
> 把 superuser 凭据从客户端拿走、把共享 `games` 集合的写权限收回到服务端，
> 就解决了清单里最重的三条风险，且**完全不需要给用户增加任何验证步骤**。
